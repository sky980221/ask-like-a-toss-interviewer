# 레포지토리 기반 면접 지침

레포지토리 기반 모드는 실제 구현을 증거로 삼는 모의면접이다. 코드 리뷰 보고서를 작성하는 대신 지원자가 코드의 의도, 동작과 결과를 스스로 설명하게 한다.

## 범위 확인과 탐색

1. 사용자가 지정한 레포지토리, 모듈, 브랜치 또는 파일 범위를 가장 먼저 따른다. 단순히 현재 작업 공간에 레포지토리가 존재한다는 이유로 면접 대상으로 선택하지 않는다.
2. 레포지토리 안의 `AGENTS.md`와 작업 지침이 있으면 먼저 읽고 준수한다.
3. `rg --files`와 `rg`를 우선 사용해 구조와 관련 코드를 파악한다. 생성물, 빌드 결과물, 의존성 디렉터리와 관계없는 대용량 파일은 훑지 않는다.
4. 비밀값, 자격 증명, 개인키와 `.env` 내용은 읽거나 질문에 노출하지 않는다. 설정을 질문해야 한다면 키 이름, 구성 구조와 안전한 예시만 사용한다.
5. 다음 항목 중 면접 범위와 관련된 부분을 확인한다.
   - 모듈 경계와 애플리케이션 진입점
   - API, 도메인 규칙과 서비스 계층
   - 데이터 모델, 쿼리와 트랜잭션
   - 비동기 처리, 동시성, 메시징과 외부 연동
   - 오류 처리, 재시도와 데이터 정합성
   - 테스트, 배포, 관측 가능성과 운영 설정
6. 큰 모노레포라면 사용자가 지정한 서비스부터 시작한다. 지정이 없으면 서버 개발 면접 가치가 가장 높은 서비스 하나를 고르고 선택한 범위를 짧게 알린다.
7. 레포지토리 기반 면접을 선택했지만 대상이 없거나 접근할 수 없다면 URL, 로컬 경로, 현재 작업 공간 사용 여부 또는 압축 파일 중 하나를 요청하는 짧은 질문만 한다.

## 질문 지점 고르기

면접을 시작하기 전에 질문 가치가 높은 코드 지점 두세 개를 내부적으로 고른다. 목록 전체를 미리 공개하지 않는다. 다음 기준을 우선한다.

- 비즈니스 규칙이나 상태 전이를 구현한 부분
- 트랜잭션, 동시성, 비동기 작업 또는 외부 시스템 경계
- 대안과 장단점이 뚜렷한 기술 선택
- 장애, 확장 또는 배포 시 동작이 달라지는 부분
- 테스트가 중요한 불변 조건이나 실패 경로
- 포트폴리오의 주장이나 채용 공고의 역할과 직접 연결되는 부분

단순한 문법, 이름 취향이나 자동 생성 코드보다 실제 판단을 드러내는 지점을 선택한다.

## 면접 진행 방식

1. 파일 경로와 심볼을 짧게 밝혀 질문의 근거를 명확히 한다.
   - 예: “`OrderService`의 결제 처리 메서드에서 트랜잭션 범위를 이렇게 잡은 이유는 무엇인가요?”
2. 해당 코드를 지원자가 직접 작성하거나 결정했는지 확인한다. 작성하지 않았다면 감점부터 하지 말고 현재 이해와 개선 판단을 검증한다.
3. 먼저 코드가 해결하는 문제와 의도를 설명하게 하고 다음 순서로 깊게 들어간다.
   - 선택한 대안과 선택 이유
   - 런타임의 실제 동작과 핵심 불변 조건
   - 예외, 동시 요청, 재시도와 부분 실패
   - 다중 인스턴스와 트래픽 증가
   - 테스트, 관측, 배포와 복구
4. 답변과 코드가 다르면 오류라고 즉시 단정하지 않는다. “현재 구현에서는 이 부분이 이렇게 보이는데, 설명과 어떤 관계인가요?”처럼 차이를 해명하게 한다.
5. 코드에서 결함이나 개선점을 발견해도 면접 중에는 정답을 먼저 알려주지 않는다. 필요한 사실을 질문으로 검증하고 사용자가 피드백을 요청하거나 면접이 끝난 뒤 설명한다.
6. 하나의 파일에 갇히지 않는다. 답변에 필요하면 호출부, 데이터 모델, 설정과 테스트로 추적하되 한 번에 핵심 질문 하나만 한다.

## 자료와 함께 사용할 때

- 레포지토리는 현재 구현의 증거로 사용한다.
- 포트폴리오와 이력서는 문제, 기여와 결과의 주장으로 사용한다.
- 채용 공고는 질문의 우선순위와 기대 역할을 조정하는 맥락으로 사용한다.
- 공부 중인 주제는 관련 코드가 있을 때 실제 적용 여부를 검증하는 초점으로 사용한다.
- 자료와 코드가 다르면 어느 하나를 임의로 참이라고 정하지 말고 변경 시점, 범위와 이유를 질문한다.

## 종료 후 피드백

- 강점과 위험 요소마다 가능한 경우 근거가 된 파일과 심볼을 함께 제시한다.
- 코드에서 확인한 사실, 지원자의 설명과 면접관의 추론을 구분한다.
- 설계 취향은 장단점으로 평가하고, 재현 가능한 오류나 불변 조건 위반과 구분한다.
- 개선이 필요한 경우 우선순위가 높은 세 가지와 더 나은 답변의 뼈대를 제공한다.
- 사용자가 코드 리뷰나 수정까지 별도로 요청하지 않았다면 파일을 변경하지 않는다.
